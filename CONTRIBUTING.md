# Contributing

Bug fixes, accessibility and performance fixes, tests, tooling and documentation corrections are
welcome. Show the failure first and keep the change narrow.

Brand values are the owner's call: the palette and type in `packages/tokens/tokens.json`, the
motion doctrine and the visual rules the gates enforce. Report a mechanical problem with one, such
as failing contrast or a generator mismatch, with reproducible evidence. Pull requests that swap in
a different palette or direction are declined.

Every change follows the [principles](README.md#principles). If it serves one product only, it
belongs in that product.

## Set up

Use Bun from [`.bun-version`](.bun-version) and Node from [`.nvmrc`](.nvmrc), then run what CI runs:

```sh
bun install --frozen-lockfile
bun run check
bun run test
bun run ci:tokens
bun run build
```

For a quicker loop, run one workspace, such as `bun run --cwd packages/ui test`. For the browser
suite, run `bun run browser:install` once, then `bun run test:browser`.

Edit `packages/tokens/tokens.json` or a generator, never a generated file. `bun run tokens:build`
rewrites `tokens.css`, `theme.css`, `packages/motion/src/tokens.ts` and `DESIGN.md`, and
`ci:tokens` fails when they drift.

On Windows, `bun install` can resolve some packages differently from Linux. A dependency change
needs a `bun.lock` generated by Bun on Linux (WSL works), because CI installs with
`--frozen-lockfile`.

## Public API and release notes

`api-reports/` records the public interface of every package but `@yesid/config`. If you change an
export, a type, a Svelte prop or a public asset:

1. Run `bun run api:report` and read the diff.
2. Run `bun run api:check` and the package's tests.

`@yesid/config` has no report; `bun run test:repository` covers its shared configs.

Any change a consumer can notice also adds a `.changes/<slug>.md` fragment naming each changed
package and its bump:

```md
---
"@yesid/ui": minor
---

What changed for consumers, and how to migrate.
```

CI accepts a changed API report only with a fragment added in the same pull request. Removing or
breaking a public contract follows [DEPRECATION.md](DEPRECATION.md).

## Defects found in a product

Reproduce the defect in the product, then fix it here with a regression test in the package that
owns the behavior. Write the test in neutral terms, with no product names in fixtures. The product
takes the fix through its next bump; never patch the installed package.

## Pull requests

Keep each pull request to one change. Say what was wrong, what you changed and which commands you
ran. Behavior changes need a test, and a change to a documented contract updates that package's
README. Commit messages state the outcome:

```text
fix(ui): keep the combobox label through the portal
```
