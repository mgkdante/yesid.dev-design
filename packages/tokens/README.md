# @yesid/tokens

Canonical design-token source and pure generation mechanics for Yesid products. This package
owns `tokens.json`, token parsing and serialization, deterministic generators, and the generated
package stylesheet. Repository and consumer adapters own physical output paths.

## Interface

- Public assets: `@yesid/tokens/tokens.json` and `@yesid/tokens/tokens.css`.
- Public mechanics: parse, serialize, types, and the four generator subpaths.
- Generated interface authority: [`api-reports/tokens.api.md`](https://github.com/mgkdante/yesid.dev-design/blob/v0.13.3/api-reports/tokens.api.md).

The internal `buildAll` module composes generators for repository tooling. It is not a public
package export. Legacy `./src/*` aliases remain compatibility surfaces until the process in
[`DEPRECATION.md`](https://github.com/mgkdante/yesid.dev-design/blob/v0.13.3/DEPRECATION.md) authorizes removal.

## Invariants and generated outputs

- `tokens.json` is the only editable token-value source.
- Generators are pure: inputs in, strings out. They do not know repository or consumer paths.
- `tools/build-tokens.ts` maps logical output to four committed artifacts: package CSS, motion
  TypeScript, the Gallery token region, and `DESIGN.md`.
- Generation order and LF bytes are deterministic across Linux and Windows.
- Generated files are never hand-edited. Change token source or generator code, then regenerate.

## Consumers and compatibility

Consumers opt into `tokens.css`; no stylesheet is injected automatically. Consumer-owned token
overrides and physical output paths stay downstream. Exact consumer receipts live only in
[`CONSUMERS.md`](https://github.com/mgkdante/yesid.dev-design/blob/v0.13.3/CONSUMERS.md).

The variable round-trip remains manual and owner-gated. `figma:push` emits a `FigmaVariable[]`
JSON document on stdout. After an operator applies it with their chosen write workflow, export a
JSON snapshot with a read workflow and pass that file to `figma:verify`. With no path argument,
the verifier reads `.tmp.figma-export.json`. No command in this package writes to Figma.

Verification is value-aware. Names, types, and modes must match exactly. `COLOR` values must be
six-hex strings and normalize ASCII hex casing only; `FLOAT` values must be finite numbers and
match exactly; `STRING` values match exactly. Descriptions are explicitly outside round-trip
parity. Snapshot parsing rejects duplicate variables and empty names, mode names, or value maps.
Never strip variable path prefixes during the handoff.

## Commands

```sh
bun run --cwd packages/tokens test
bun run --cwd packages/tokens check
bun run --cwd packages/tokens figma:push
bun run --cwd packages/tokens figma:verify -- /path/to/variable-snapshot.json
bun run tokens:build
bun run ci:tokens
```

## Failure modes and release implications

Invalid DTCG shapes, incomplete clamp tokens, duplicate Figma names, stale generated bytes, or
platform-dependent serialization fail their owning tests or drift gates. Fix the source owner;
never normalize a failing derivative by hand.

Token values, public exports, generators, or package documentation change the coordinated release
payload. Use a release fragment and the process in [`RELEASING.md`](https://github.com/mgkdante/yesid.dev-design/blob/v0.13.3/RELEASING.md). Public
interface changes also require a regenerated API report. Product-specific values or policy do not
belong here; see [`BOUNDARIES.md`](https://github.com/mgkdante/yesid.dev-design/blob/v0.13.3/BOUNDARIES.md).
